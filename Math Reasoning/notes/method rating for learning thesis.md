# Method 5 — Proof reconstruction loop

### What you produce (deliverables)

1. **Theorem Queue (1 page):** list of theorems/propositions you will process, in reading order, with checkbox status: _Seen / Skeleton OK / Recalled 24h / Recalled 1w_.
    
2. **Proof Skeleton Cards (one per result):** each card is 5 fields (below).
    
3. **Gap Ledger (running):** every missed step is logged as: _Gap → what I needed → fix next session_.
    
4. **Recall Sheets:** one-page reconstructions (closed-book) at 24 hours and 1 week.
    

This method is justified by the “testing effect” / retrieval-practice literature: reconstruction and recall outperform rereading for long-term retention. ([PubMed](https://pubmed.ncbi.nlm.nih.gov/21252317/ "Retrieval practice produces more learning than elaborative studying with concept mapping - PubMed"))

---

## The 5-field Proof Skeleton Card (template)

For each theorem/proposition:

1. **Statement** (clean, exact)
    
2. **Depends on** (1–3 prior results/definitions)
    
3. **Key move** (one sentence: the decisive idea)
    
4. **Skeleton** (5–10 lines: the spine of the proof)
    
5. **Used for** (where it gets invoked later)
    

Keep it skeletal. If you write paragraphs, you’re hiding that you can’t reconstruct.

---

## The loop (per theorem/proposition)

### Step 0 — Select (30 seconds)

Pick exactly **one** result from the paper’s main spine (division / Bézout / Euclid lemma / irreducible ⇒ field / etc.).

### Step 1 — Read the statement (2–4 minutes)

- Read slowly until you can say (out loud or in your head):  
    “This claims ___ under hypotheses ___, and the conclusion is ___.”
    
- Fill **Field 1 (Statement)** and **Field 2 (Depends on)** on the card.
    

### Step 2 — Predict the proof move (1 minute)

Before seeing the proof, write **Field 3 (Key move)** as a guess:

- “The move will be: reduce degree / minimal counterexample / contradiction / Bézout combination / etc.”
    

This forces active control instead of passive recognition.

### Step 3 — Cover the proof (no peeking)

Literally cover or scroll away the proof.

### Step 4 — Write the skeleton from memory (6–10 minutes)

Fill **Field 4 (Skeleton)** closed-book.

**Rules:**

- Every line must be an actual inference step (“there exists…”, “choose…”, “apply…”, “therefore…”), not “then some algebra.”
    
- If you hit a blank, write **[GAP]** and keep going. Don’t stall.
    

### Step 5 — Re-open and mark exact gaps (4–8 minutes)

Compare your skeleton to the proof and annotate only with:

- **Missing lemma/definition**
    
- **Unjustified inference**
    
- **Wrong dependency**
    
- **Wrong direction (if-and-only-if confusion)**
    

Then log each error into the **Gap Ledger**:

- **Gap:** “I don’t see why step X implies step Y.”
    
- **Needed:** “Lemma/definition Z.”
    
- **Fix next:** “Rewrite skeleton with Z explicitly; do one micro-drill: restate Z and apply it once.”
    

### Step 6 — Immediate re-run (optional but powerful, 3 minutes)

Close the proof again and rewrite just the corrected skeleton in 5–7 lines.

This is where the learning happens; it is retrieval with feedback. ([SAGE Journals](https://journals.sagepub.com/doi/10.1111/j.1467-9280.2006.01693.x?utm_source=chatgpt.com "Test-Enhanced Learning - Henry L. Roediger, Jeffrey D. ..."))

## Method 7 — Directness: use the theory immediately

### What you produce (deliverables)

1. **Mini-Drill Pack (per session):** 3 problems + your full solutions + 3-line reflection (“what theorem I used / where I hesitated / what to drill”).
    
2. **Justification Layer:** every solution must cite the _structural reason_ it is valid (division theorem ⇒ remainder; Euclidean algorithm ⇒ gcd; quotient definition ⇒ reduction).
    
3. **Transfer Set (weekly):** 3 self-invented exercises that are not copied from the PDF, each tagged by which theorem it tests.
    
4. **Gap Ledger:** any step you cannot justify immediately becomes: _Gap → needed lemma → fix next session_.
    

This is “direct practice” in Ultralearning terms: don’t just read the mechanism—execute it.

## Session recipe (60–90 minutes)

### Step 0 — Pick one “module” (1 minute)

Choose exactly one of these modules per session:

- **M1:** Division theorem → remainder uniqueness
    
- **M2:** Euclidean algorithm → gcd (+ Bézout if you’re ready)
    
- **M3:** Congruence mod m(x)m(x)m(x) → unique remainder representative
    
- **M4:** Quotient ring multiplication → reduce using the relation m(x)=0m(x)=0m(x)=0 in the quotient
    

Do not mix modules until you can do one cleanly.

## The core loop (repeat 3 times)

### Step 1 — Read a micro-chunk (5–8 minutes)

Read only the statement and the proof idea for the module. Stop as soon as you can write:

- **What it guarantees**
    
- **What inputs you’re allowed**
    
- **What the output is and why it’s unique**
    

### Step 2 — Immediate exercise (10–15 minutes)

Do **one** exercise right away, using abstract polynomials (no numeric busywork required).

#### Exercise type A — gcd via Euclidean algorithm (module M2)

- **Task:** Given nonzero f,g∈F[x]f,g\in F[x]f,g∈F[x], produce the Euclidean chain  
    f=q1g+r1,  g=q2r1+r2,…f = q_1 g + r_1,\; g = q_2 r_1 + r_2,\dotsf=q1​g+r1​,g=q2​r1​+r2​,… until remainder 000.  
    Then declare the last nonzero remainder as gcd⁡(f,g)\gcd(f,g)gcd(f,g) (normalized monic if desired).
    
- **Justification line you must write:** “This works because division in F[x]F[x]F[x] strictly decreases degree of remainders.”
    

#### Exercise type B — reduce mod m(x)m(x)m(x) to unique remainder (module M3)

- **Task:** Given h,m∈F[x]h,m\in F[x]h,m∈F[x] with m≠0m\neq 0m=0, compute the unique rrr with deg⁡r<deg⁡m\deg r < \deg mdegr<degm such that h≡r(modm)h \equiv r \pmod{m}h≡r(modm).
    
- **Justification line you must write:** “Existence/uniqueness of this representative is exactly the division theorem.”
    

#### Exercise type C — quotient-ring multiplication (module M4)

- **Task:** In F[x]/(m(x))F[x]/(m(x))F[x]/(m(x)), multiply two classes [a(x)]⋅[b(x)][a(x)]\cdot[b(x)][a(x)]⋅[b(x)] by:
    
    1. multiply in F[x]F[x]F[x] to get a(x)b(x)a(x)b(x)a(x)b(x),
        
    2. reduce the product to the unique remainder r(x)r(x)r(x) with deg⁡r<deg⁡m\deg r < \deg mdegr<degm,
        
    3. report [r(x)][r(x)][r(x)] as the product.
        
- **Justification line you must write:** “Multiplication is well-defined on congruence classes; reduction uses the defining relation m(x)=0m(x)=0m(x)=0 in the quotient.”
    

(If the PDF gives a concrete relation like x2≡−1x^2\equiv -1x2≡−1, treat it as a _special case_ of “reduce using m(x)m(x)m(x).” )

### Step 3 — Reflection (2 minutes)

Write exactly three lines:

1. The theorem you used (by name).
    
2. The single step that felt least automatic.
    
3. What you will drill next time (one micro-skill).
    

### Step 4 — Micro-variation (5 minutes)

Change one feature and redo quickly:

- swap f,gf,gf,g roles,
    
- change degrees,
    
- switch to “coprime vs non-coprime,”
    
- change whether mmm is irreducible (later this matters for “field vs not field”).
    

This is how you force generalization instead of memorizing one pattern.

## Weekly review — Transfer set (the rating instrument)

Once per week, invent **3 new exercises** (templates are fine) and solve them under mild time pressure:

1. **One gcd exercise** (M2)
    
2. **One reduction mod mmm** (M3)
    
3. **One quotient multiplication** (M4)
    

### Scoring (simple and ruthless)

For each exercise, score 0–2 on each axis:

- **Correctness (0–2):** final output correct
    
- **Justification (0–2):** you named the theorem and used it properly
    
- **Fluency (0–2):** you didn’t stall or “handwave the key step”
    

Total per exercise: 0–6. Weekly total: 0–18.

If your correctness is fine but justification is weak, you’re doing pattern-matching, not mathematics.
